01 / Approach

Good analysis is more than a good-looking chart.

I focus on making the work understandable and reviewable—from the first data check to the final explanation.

Ask a useful question. Check the data. Explain what the result actually means.

My projects are learning projects, not claims of production consulting experience. I aim to show the dataset, preparation steps, analysis logic and limitations so a reviewer can follow the work and decide what should be tested next.

01 / DATA QUALITY

Trust the input

Look for missing values, duplicates, unusual records and inconsistent categories before analysing.

02 / ANALYSIS

Follow the question

Choose SQL, spreadsheets, Python or BI tools based on the problem—not just the tool I want to use.

03 / COMMUNICATION

Show the limits

Separate observed patterns from assumptions, and make it clear when a result needs validation.
