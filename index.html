01 / My approach

A chart is the output.
The thinking is the work.

I want each project to be understandable, reviewable and honest about what its data can—and cannot—tell us.

Ask a useful question. Check the data. Explain what the result actually means.

My projects are learning projects, not claims of production consulting experience. I aim to show the dataset, preparation steps, analysis logic and limitations so a reviewer can follow the work and understand what should be tested next.

01 / DATA QUALITY

Start with trust

Check missing values, duplicates, unusual records and inconsistent categories before analysing.

02 / ANALYSIS

Choose the right tool

Use SQL, spreadsheets, Python or BI based on the question—not just the tool itself.

03 / COMMUNICATION

Respect the evidence

Separate observed patterns from assumptions and state where a result needs validation.
